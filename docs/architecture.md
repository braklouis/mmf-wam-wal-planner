# 配置测算器：职责与边界

本工具回答：在输入的期限、集中度与报价额度约束下，新增资金如何配置以最大化组合加权 YTM。目标 YTM 反推使用“至少达到”，不增加 WAM/WAL 锚定模式。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `lib/planner.ts` | 兼容原有调用方的公开入口，不包含计算实现 |
| `lib/planner-types.ts` | 组合、持仓、报价和结果类型 |
| `lib/simplex.ts` | 非负右端项 LP 求解，不依赖金融业务与 UI |
| `lib/planner-core.ts` | 输入校验、现金压力、申购优化、同比例赎回 |
| `lib/frontier.ts` | 调用核心优化，构建收益前沿与目标收益反推 |
| `lib/portfolio-input.ts` | 三种输入模式的数据来源与转换 |
| `components/planner-fields.tsx` | 数值编辑、校验显示、指标展示 |
| `components/frontier-panel.tsx` | 收益曲线与目标收益交互，不自行求解 |
| `app/page.tsx` | 工作区状态、页面组合与用户操作 |

依赖方向：公开入口 → 前沿/核心 → 求解器。内部模块直接引用依赖，不反向引用公开入口。此次拆分保留原计算函数和公开接口；页面编排与核心业务仍较大，后续按具体变更继续拆分，避免一次性重写数学模型。

## 结果解释

- “已建模约束通过”仅表示当前模型校验通过，不是全面合规结论。
- 简易模式不校验集中度；持仓模式从逐笔持仓推导指标；汇总期限模式仅手填 WAM/WAL。
- 输入变化后，已有配置标为“待重新计算”；收益前沿与已计算配置有不同更新时点。
- 加权 YTM 不是完整债券现金流估值；现金压力不等于完整流动性压力测试；同比例赎回并不验证资产实际可变现性。
- 报价、持仓、适用实体/集团限额由用户维护。工具不验证行情时效、资产资格、信用评级或全部监管要求，也不作为交易执行或会计账本。

## 变更验证

保持独立 LP oracle、数值边界、模式数据来源、反推、持仓与加密存储测试。调整模块边界时运行全量测试、类型检查及构建；业务组件纳入 lint，避免新增组件遗漏检查。监管规则扩展应独立核实权威来源后实施，不能由“覆盖评分”推导出具体要求。
