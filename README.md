# MMF WAM/WAL 规划器

一个本地优先的货币市场基金（MMF）配置测算工具。它把当前组合、持仓、金融机构集中度和当日报价放在同一套口径下，用于比较净申购配置、WAM/WAL 收益前沿，以及同比例净赎回后的组合状态。

> 当前版本是内部测算草案。“约束通过”只表示已建模的约束通过，不等同于完整的 SFC 合规结论，也不替代投资经理、风控或合规复核。

## 当前功能

- 在“当前持仓与机构”中维护持仓、机构归属、集中度上限和合作机构备选库。
- 用连续金额线性规划，在净申购金额、WAM、WAL、机构集中度和单项报价额度内最大化交易后 YTM。
- 分别展示 WAM / WAL 上限与最高可达 YTM 的收益前沿。
- 输入目标交易后 YTM，反推所选 WAM 或 WAL 的最短上限及对应配置。
- 按全部持仓同比例测算净赎回，复核交易后持仓、机构敞口和期限上限。
- 对求解结果再次执行金额、期限、机构额度和产品额度硬约束复核。
- 左上角可即时切换简体中文、繁体中文和英文，并切换浅色或深色模式。

## 推荐使用顺序

1. 在“当前持仓与机构”录入完整持仓，并把需要纳入单一机构统计的项目归到对应机构。
2. 确认持仓合计等于当前 AUM，再设置各机构适用的集中度上限。
3. 回到“配置测算”，选择净申购或净赎回，填写组合指标和交易金额。
4. 净申购时更新当日报价、WAM/WAL 天数、利率和可用额度，再计算最优配置或查看收益前沿。
5. 对结果做人工产品资格、发行实体/集团归属和完整合规复核后再使用。

## 计算口径

### 输入约定

- 页面内所有金额共用右上角选择的金额单位；该选择只改变显示标签，不对数值做换算。
- YTM 和报价利率按百分数输入，例如 `2.5` 表示 `2.5%`。
- 当前机构敞口由持仓按机构归属自动汇总，不是另一份独立金额输入。
- 未归属机构的持仓不进入本工具的单一机构集中度统计；能否排除必须人工确认。
- 浮息报价的 WAM 天数可以单独填写；留空时，模型使用该报价的 WAL 天数作为 WAM 天数。

### 净申购

设当前 AUM 为 `A`、新增资金为 `B`、当前组合 YTM 为 `y₀`，报价 `i` 的配置金额、利率、WAM 和 WAL 分别为 `xᵢ`、`rᵢ`、`mᵢ`、`lᵢ`。模型最大化交易后 YTM：

```text
max  (A × y₀ + Σ xᵢ × rᵢ) / (A + B)
```

主要约束为：

```text
Σ xᵢ ≤ B
(A × 当前 WAM + Σ xᵢ × mᵢ) / (A + B) ≤ WAM 上限
(A × 当前 WAL + Σ xᵢ × lᵢ) / (A + B) ≤ WAL 上限
机构现有敞口 + 该机构新增配置 ≤ 机构上限 × (A + B)
0 ≤ xᵢ ≤ 单项报价额度
```

允许存在未配置资金 `B - Σxᵢ`；当前版本把它视为零收益、零 WAM、零 WAL 的现金。

### 净赎回

当前版本只做同比例情景，不选择具体赎回产品，也不判断赎回优先级。设净赎回额为 `R`，每项当前持仓为 `hᵢ`：

```text
赎回后持仓ᵢ = hᵢ × (1 - R / A)
```

因此在该假设下，组合 YTM、WAM、WAL 和各机构占比理论上保持不变；系统仍会按交易后 AUM 重新汇总并复核。全部赎回不支持，因为交易后不存在可计算的组合指标；过于接近全额赎回、已超出可靠浮点精度的输入也会被拒绝。

### 收益前沿与目标 YTM

- 收益前沿按整数天采样，并补入理论最紧点和估算的最大 YTM 起点；它不是任意精度的连续枚举。
- 目标 YTM 反推只用于净申购。系统寻找所选 WAM 或 WAL 的最短可行上限，另一项当前上限仍然生效。
- 反推结果展示到 `0.01` 天，并向上取整以避免显示值低于实际可行边界。

## 合规边界

当前模型自动检查的范围包括：

- 交易后组合 WAM 不超过 60 天，WAL 不超过 120 天；用户可以设置更严格的上限。
- 用户设置的单一机构集中度上限，输入最高不超过 25%。
- 单项报价额度、总配置金额、持仓/AUM 对账和基础数值关系。
- 净申购及净赎回结果的交易后硬约束复核。

页面把 10% 作为一般单一实体提示线；10%–25% 只是可录入的例外区间，必须由使用者确认适用条件。当前版本不会自动判断单项工具 397 天限制、产品资格、发行实体及集团合并、DLA/WLA 或其他 SFC 条件。内部类型名仍有 `Bank` 的历史命名，但业务口径应理解为金融机构。

## 数据保存

“合作机构备选库”、界面语言和明暗主题保存在当前浏览器的 `localStorage` 中，键名分别为：

```text
mmf-planner.bank-library.v1
mmf-planner.locale.v1
mmf-planner.theme.v1
```

当前组合、交易金额、持仓、当日报价、当前机构表和金额单位目前只保存在页面内存中；刷新会恢复示例值。“恢复示例”不会删除已保存的合作机构备选库。

## 代码结构

```text
app/
  layout.tsx          页面元数据与根布局
  page.tsx            客户端界面、表单状态、两个工作区、图表和浏览器存储
  globals.css         全局样式
components/
  i18n-provider.tsx   三语界面上下文
lib/
  i18n.ts             语言、主题偏好及界面文案翻译
  planner.ts          类型、默认数据、校验、敞口汇总、求解器、前沿和反推
tests/
  i18n.test.ts        语言、主题偏好和动态文案回归测试
  planner.test.ts     数学引擎与硬约束回归测试
components/ui/        通用 UI 组件库存；页面目前只使用其中一部分
public/               静态资源
vite.config.ts        Vinext、Sites 与 Cloudflare 的本地构建配置
.openai/hosting.json  可选托管资源绑定；当前未配置 D1 / R2
```

目前最重要的边界是：`app/page.tsx` 负责交互和展示，`lib/planner.ts` 负责纯计算与校验。修改数学逻辑时应优先在 `lib/planner.ts` 中完成，并同步补充 `tests/planner.test.ts`；不要把计算规则散回 JSX。

## 修改后的最低检查

```bash
npm run typecheck
npm test
npm run build
```

若修改了数学引擎，至少覆盖配置总额、WAM、WAL、机构集中度、单项额度、小金额尺度和近全额赎回边界。提交前再运行 `npm run lint` 并检查 `git diff --check`。
