# MMF WAM/WAL 规划器

一个本地优先的货币市场基金（MMF）配置测算工具。它把当前组合、持仓、金融机构集中度和当日报价放在同一套口径下，用于比较净申购配置与 WAM/WAL 收益前沿。净赎回功能尚未完善，入口和赎回示例已置灰禁用。

> 当前版本是内部测算草案。“约束通过”只表示已建模的约束通过，不等同于完整的 SFC 合规结论，也不替代投资经理、风控或合规复核。

## 当前功能

机构维护合并为一步：填写名称和上限后点击“新增机构”，即加入当前测算并自动保存到本机；已有机构从“选择已有机构”下拉框直接选择加入，无需再分别执行“存入备选库”和“加入机构表”。同名机构不会重复加入。

- 在“当前持仓与机构”中维护持仓、机构归属、集中度上限和合作机构备选库。
- 用连续金额线性规划，在净申购金额、WAM、WAL、机构集中度和单项报价额度内最大化交易后 YTM。
- 分别展示 WAM / WAL 上限与最高可达 YTM 的收益前沿。
- 输入目标交易后 YTM，反推所选 WAM 或 WAL 的最短上限及对应配置。
- 净赎回暂不可用：旧同比例模型仅保留为内部代码与回归测试，不作为可用业务功能。
- 对求解结果再次执行金额、期限、机构额度和产品额度硬约束复核。
- 左上角可即时切换简体中文、繁体中文和英文，并切换浅色或深色模式。

## 使用方式

页面分为“当前持仓”“今日可投”“配置测算”三个工作区，分别维护持仓与机构、产品与报价，以及组合参数与优化结果。示例切换统一位于顶部，切换工作区不会清除已输入数据；计算按钮保留在配置测算的参数区下方。

1. 先在“当前持仓与机构”同步最新持仓，并建立每笔持仓的归属机构；未归属项仅按你后续定义参与统计。
2. 配置每个机构的集中度上限与当日可选合作机构。
3. 在“配置测算”区间输入新增资金、WAM/WAL 目标与风险参数，执行净申购场景模拟。
4. 查看优化结果、收益前沿与约束复核，并结合产品资质、发行实体与集团口径完成人工复核。

## 推荐使用顺序

1. 在“当前持仓与机构”录入完整持仓，并把需要纳入单一机构统计的项目归到对应机构。
2. 确认持仓合计等于当前 AUM，再设置各机构适用的集中度上限。
3. 回到“配置测算”，在净申购模式下填写组合指标和新增资金金额。
4. 在“今日可投”更新产品报价、WAM/WAL 天数、利率和可用额度，再回到“配置测算”计算最优配置或查看收益前沿。
5. 对结果做人工产品资格、发行实体/集团归属和完整合规复核后再使用。

## 计算口径

### 输入与结果一致性

- 数字支持粘贴规范千位分隔（例如 `1,000.50`）；不把逗号当小数点，歧义格式不接收。
- 只读汇总数值最多显示三位小数，计算仍使用未舍入值。
- 输入变化后隐藏上次配置，重新计算后再显示；收益前沿只显示与当前输入对应的曲线。
- 空持仓组合的当前指标为零，可开始新组合测算；非零持仓缺失收益率或期限时仍阻止计算。
- 持仓加权先计算权重，避免极大金额乘收益率时溢出；重复的数据标识会被拒绝。

### 当前指标由持仓自动汇总

“当前组合与目标”中的 AUM、加权 YTM、WAM、WAL 为只读值。AUM 为持仓当前估值金额合计，其余三项按该金额加权；新增资金和目标上限仍手动输入。现金缓冲与机构敞口也从持仓汇总。

每笔正金额持仓填写当前估值 YTM、剩余 WAL 天数，以及适用的 WAM 天数（固定利率产品可留空采用 WAL；浮息产品填剩余重定价天数）。现金 WAM/WAL 自动为 0，但收益率仍需填写，无息现金明确填 0。零金额行不影响汇总。缺失数据或 WAM 大于 WAL 等无效期限会阻止测算，不按零收益处理。

加权 YTM 是组合年化收益水平的近似指标，不是指定持有期的现金流收益预测；金额需使用同一估值日和记账币种。剩余天数目前手动维护，尚未按到期日自动滚动。

### 输入约定

- 页面内所有金额共用右上角选择的金额单位；该选择只改变显示标签，不对数值做换算。
- YTM 和报价利率按百分数输入，例如 `2.5` 表示 `2.5%`。
- 当前机构敞口由持仓按机构归属自动汇总，不是另一份独立金额输入。
- 未归属机构的持仓不进入本工具的单一机构集中度统计；能否排除必须人工确认。
- 浮息报价的 WAM 天数可以单独填写；留空时，模型使用该报价的 WAL 天数作为 WAM 天数。

### 净申购

设当前 AUM 为 `A`、新增资金为 `B`、当前组合 YTM 为 `y₀`，报价 `i` 的配置金额、利率、WAM 和 WAL 分别为 `xᵢ`、`rᵢ`、`mᵢ`、`lᵢ`。模型最大化交易后 YTM：

```text
max  (A × y₀ + Σ xᵢ × rᵢ) / (A + B)
```

主要约束为：

```text
Σ xᵢ ≤ B
(A × 当前 WAM + Σ xᵢ × mᵢ) / (A + B) ≤ WAM 上限
(A × 当前 WAL + Σ xᵢ × lᵢ) / (A + B) ≤ WAL 上限
机构现有敞口 + 该机构新增配置 ≤ 机构上限 × (A + B)
0 ≤ xᵢ ≤ 单项报价额度
```

允许存在未配置资金 `B - Σxᵢ`；当前版本把它视为零收益、零 WAM、零 WAL 的现金。

### 净赎回（暂不可用）

页面入口与赎回示例已禁用并置灰。以下是保留模型的技术说明，不代表目前支持真实赎回决策；产品级可赎回性、到账时点及赎回来源选择仍待完善。

当前版本只做同比例情景，不选择具体赎回产品，也不判断赎回优先级。设净赎回额为 `R`，每项当前持仓为 `hᵢ`：

```text
赎回后持仓ᵢ = hᵢ × (1 - R / A)
```

因此在该假设下，组合 YTM、WAM、WAL 和各机构占比理论上保持不变；系统仍会按交易后 AUM 重新汇总并复核。全部赎回不支持，因为交易后不存在可计算的组合指标；过于接近全额赎回、已超出可靠浮点精度的输入也会被拒绝。

### 收益前沿与目标 YTM

- 收益前沿按整数天采样，并补入理论最紧点和估算的最大 YTM 起点；它不是任意精度的连续枚举。
- 目标 YTM 反推只用于净申购。系统寻找所选 WAM 或 WAL 的最短可行上限，另一项当前上限仍然生效。
- 反推结果展示到 `0.01` 天，并向上取整以避免显示值低于实际可行边界。

## 合规边界

当前模型自动检查的范围包括：

- 交易后组合 WAM 不超过 60 天，WAL 不超过 120 天；用户可以设置更严格的上限。
- 用户设置的单一机构集中度上限，输入最高不超过 25%。
- 单项报价额度、总配置金额、持仓/AUM 对账和基础数值关系。
- 净申购及净赎回结果的交易后硬约束复核。

页面把 10% 作为一般单一实体提示线；10%–25% 只是可录入的例外区间，必须由使用者确认适用条件。当前版本不会自动判断单项工具 397 天限制、产品资格、发行实体及集团合并、DLA/WLA 或其他 SFC 条件。内部类型名仍有 `Bank` 的历史命名，但业务口径应理解为金融机构。

## 数据保存

“合作机构备选库”、界面语言和明暗主题保存在当前浏览器的 `localStorage` 中，键名分别为：

```text
mmf-planner.bank-library.v1
mmf-planner.locale.v1
mmf-planner.theme.v1
```

当前组合、交易金额、持仓、当日报价、当前机构表和金额单位目前只保存在页面内存中；刷新会恢复示例值。“恢复示例”不会删除已保存的合作机构备选库。

## 现金缓冲与手动赎回压力

在持仓表将纯现金标记为“现金 · 计入缓冲”；其他资产与补足对账的资产不会自动计入现金。示例现金为 5，当前 AUM 为 100。5% 仅为参考目标，实际现金由持仓汇总，不自动补足或将新增未配置资金计入已确认现金。

压力金额 = 当前 AUM × 手动压力比例（页面默认 2%）。申购的压力后 AUM = 当前 AUM + 新增资金 − 压力金额。各机构配置金额上限 = 压力后 AUM × 该机构适用上限；最多新增 = 此上限减去已有敞口。优化、收益前沿及目标收益反推共用这个约束。

压力等于现金时允许计算；超过现金时停止申购优化，需要补充 T+0 可赎回资产和额度后才能扩展模型。该情景保守地维持全部机构敞口不变（包括归属银行的现金），不模拟现金账户支付顺序。压力后的 AUM 仅用于机构额度，不作为交易完成后的收益或期限指标。该压力约束继续用于申购优化，与已禁用的净赎回工作流分开。

## 12 家银行模拟示例

点击“12家银行模拟示例”会替换当前页面的组合、持仓和报价，载入净申购示例；“恢复示例”可恢复基础示例。

- 香港：汇丰、恒生、中银香港、东亚银行。
- 新加坡：星展、华侨、大华、渣打银行。
- 沙特：Saudi National Bank、Al Rajhi Bank、Riyad Bank、Saudi Awwal Bank。
- 每家 2–3 个产品，共 30 个产品、31 笔持仓（含现金）；AUM 480 亿元，新增资金 48 亿元，现金 60 亿元，现金赎回压力 48 亿元。
- 使用固定种子的伪随机数据，金额保留两位小数；各银行敞口、产品持仓、额度、期限与利率有差异，每次载入可复现。
- 银行名称仅用于展示；产品、利率、金额及统一 10% 集中度上限均为模拟假设，不代表实际报价、产品可售性或机构资格。所有金额视为同一记账币种，不进行跨币种汇率或对冲测算。
- 回归测试覆盖金额尺度切换、申购约束、收益前沿及旧赎回模型的金额对账；测试通过不代表赎回业务功能已完善。
